## 1. 판정

**필수 요구사항 128건 중 124건 DONE, 4건 BLOCKED. 선택 요구사항 6건은 미승인.**

BLOCKED 4건은 모두 운영 인프라 항목이며, 그중 2건(백업·복구)은 **운영 전환 차단 항목**이다. 이 둘이 해소되기 전에는 실데이터를 올려서는 안 된다. 나머지 2건(브라우저 매트릭스·동시 사용자)은 검증 수단이 없어 미측정 상태이며 기능 결함은 아니다.

기능 요구사항(BAS·SLS·INV·ACC·APV·HRM·RPT·UIX) 85건은 전건 DONE이다.

1년치 분포 실데이터에서 측정한 값이다. 빈 데이터베이스에서 잰 수치는 의미가 없으므로 데이터를 채운 뒤 측정했다.

| 요구사항 | 목표 | 최댓값 |
|---|---|---|

| NFR-PERF-02 전표 저장 | 1초 | 75ms (확정까지 529ms) |

## 5. 이관 대사

MIG-01~09 전 대상에 대해 검증·반영·대사 3단계를 구현했고, 대사는 `/system/migration` 화면에서 원천 대비 반영 건수와 합계 차이를 대상별로 보여준다. 이관 멱등성은 배치가 아니라 `(대상유형, 원천키)`에 걸어 두었다 — 같은 파일을 두 번 올려도 두 번 반영되지 않는다. 과거 문서는 참조 전용으로 이관해 매출·재고에 이중 계상되지 않도록 했다.

실데이터 이관 대사 결과서는 실제 이관 시점에 이 화면의 출력으로 작성한다. 현재는 시험 데이터에 대한 대사만 수행했다.

## 6. 복구 결과

**미수행.** 복구 절차는 `docs/operations.md`에 문서화했으나 스테이징 복구시험을 실제로 하지 않았고, 자동 백업 작업 자체가 구현되어 있지 않다. 따라서 RPO·RTO는 목표값일 뿐 측정값이 아니다. NFR-OPS-03·04로 BLOCKED 처리했으며 운영 전환 전 필수 항목이다.

## 7. 검수 과정에서 발견해 고친 결함

STEP 13의 세 가지 감사(요구사항 누락·트랜잭션 경계·민감정보)를 수행한 결과, **DONE으로 보고되어 있었으나 근거가 성립하지 않는 요구사항 27건**과 다수의 실제 결함이 드러났다. 추적표는 인용된 파일이 존재하는지는 보지만 그 파일이 요구사항을 실제로 구현·검증하는지는 보지 않기 때문이다. 감사 기록은 `docs/audit-step13.md`에 남겼다.

### 가장 큰 원인: 도달할 수 없는 기능

라우터에 선언된 tRPC 프로시저 236건 중 **54건을 어느 화면도 호출하지 않았고**, 메뉴 링크 60건 중 8건이 404였다. 서버 기능이 있고 통합시험이 통과해도 화면에서 부를 수 없으면 사용자 입장에서 그 요구사항은 없는 것과 같다. 화면 12개를 신설하고 기존 화면을 연결해 현재 도달 불가 프로시저는 0건, 끊어진 링크는 0건이다.

### 보안 결함

| 결함 | 영향 |
|---|---|
| 비밀번호 변경 화면 부재 | 관리자가 발급한 임시 비밀번호를 사용자가 바꿀 방법이 없어, 관리자가 아는 비밀번호를 계속 사용 |
| 첨부 URL이 사용자에 묶이지 않음 | 유출된 링크가 계정 없이도 열리는 무기명 토큰으로 동작 |
| 결재 보류를 아무나 해제 | 보류를 건 결재자가 아닌 사람이 문서를 다시 결재 대기로 되돌릴 수 있음 |
| 목록 5종에 사업부 범위 미적용 | 타 사업부의 견적·주문·구매요청·발주·매입전표가 그대로 조회됨 |
| 필터로 데이터 범위 우회 | 원장·전표·재고전표에서 남의 사업부·창고 id를 지정하면 그대로 열림. 화면은 그런 요청을 보내지 않으므로 UI로는 발견 불가 |
| 사용자 권한 편집이 범위를 통째로 교체 | 역할만 바꿔도 부문·창고 권한이 조용히 삭제됨 |
| 운영 기본 비밀값 미검증 | 기본 암호화 키·세션 시크릿으로 운영 기동 가능 |

### 데이터 정합성 결함

| 결함 | 영향 |
|---|---|
| 확정 견적서 수정 가능 | 고객에게 보낸 견적의 금액을 흔적 없이 변경 가능 (INT-03 위반) |
| 주문 연동 매출전표 수정 | 주문의 잔여수량이 되살아나 출고했는데 미출고로 회귀 |
| 예약작업 핸들러 미등록 | 계약만료 알림·장기미결 알림·개인정보 파기가 전부 조용히 폐기되면서 아웃박스는 성공으로 기록 |
| 예약작업 발생기 부재 | 핸들러를 붙인 뒤에도 두 작업은 이벤트를 만드는 곳이 없어 영원히 실행되지 않음 |
| 개인정보 파기 도달 불가 | 라우터도 화면도 없어 보유기간 의무를 이행할 방법이 없음 |
| 검색어 무시 | 범위가 있는 사용자가 검색하면 조건이 사라지고 범위 내 전체가 반환. 관리자로는 재현 불가 |
| 첨부 저장이 트랜잭션 내부 | 롤백된 업로드가 저장소에 고아 파일로 잔류 |
| 주민번호 마스크 자릿수 | 표시 자리에 성별 자리가 아닌 값이 노출 |

모든 수정에는 회귀시험을 붙였고, 여러 건은 수정을 되돌려 시험이 실제로 실패하는지 확인했다. 시험이 없는 수정은 다음 변경에서 다시 무너진다.

## 9. 결정사항

DEC-01~09는 RFP 기본안을 채택했다. 재고평가는 월 이동평균, 원단위 절사, 결재 기준금액과 전결 규정, 회계기간 운영, 취업규칙 연차, 개인정보 보유기간, 이관 범위, 알림 채널(메신저 미연동)이 모두 여기에 해당한다. 근거와 판단은 `docs/decision-register.md`와 `docs/adr/`에 있다. 정책은 모두 버전과 시행일을 갖고, 새 버전을 발행해도 이미 결정된 문서는 소급해 바뀌지 않는다.

## 11. 운영 전환 전 권고

1. **백업과 복구시험을 먼저 마칠 것.** 이 둘이 없으면 첫 장애가 곧 데이터 손실이다.
2. 최초 관리자 계정의 임시 비밀번호를 로그인 즉시 변경할 것. 앱이 강제하지만, 변경 전까지는 시드에 적힌 비밀번호로 접근 가능한 계정이다.
3. 운영 환경 변수를 실제 값으로 채울 것. 기본 암호화 키·세션 시크릿으로는 기동이 거부되지만, 거부를 확인하는 것보다 미리 채우는 편이 낫다.
4. Safari·Edge에서 핵심 흐름을 한 번 걸어볼 것.
5. 동시 사용자 목표를 정하고 부하시험을 수행할 것.
